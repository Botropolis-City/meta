# The settled daemon after item 196, against r873, 2026-10-22

**Rig:** Intel Core Ultra 7 265U, 14 threads, 62 GiB; integrated Arrow Lake-U GPU (not used: no city was opened); 1920×1200, i3 on X11, Arch Linux, kernel 7.2.
It is the machine of [the item 157 report](2026-10-21-ultra7-265u-igpu-item-157.md), whose r873 is this report's baseline, and like it has far more RAM than the reference machine in [budgets.md](../budgets.md), so every figure is judged against the budgets.
**Builds:** r873 (`be5360c`), item 157, the baseline [item 196](../../roadmap/196-a-settled-daemon-bursts-to-several-cores-on-rescans.md) was filed against; r890 (`e625afd`), item 196's slices 1–3; each built with `go build ./cmd/botropolisd` from `git archive`, go 1.27.3.
**History on disk:** 212 transcripts, 3.2 GiB, 146 projects, 11 written in the last hour, 31 `claude` processes running.
**Runs:** daemon A/B, 600 s at 2 s, both builds side by side against the live home, at 03:20 MDT, holding the landing lock so no landing's tests shared the cores.

## Findings

1. **The settled daemon meets its CPU budget**: r890 averaged 0.7% of a core with 5.4% at p95, against ≤ 2% and ≤ 25%; r873 averaged 1.6% and 11.9% beside it (A/B, without the first minute).
   **This was a quiet night**: r873 itself read 7.6% settled in the item 157 run with item sessions busy, against 1.6% here, so 0.7% is not the busy case.
   The loaded case is the acceptance test, `TestSettledDaemonUnderAStreamOfChanges`: on the synthetic home plus 200 stopped sessions, one writing every 200 ms, r878 used 8.6–14.5% of a core and r890 1.2–1.8% with the machine at load 20–26.
2. **It no longer re-reads what it already has**: settled reads fell from 1.0 MiB/s mean, 8.0 at p95 and 20.3 at peak to 0.1, 0.5 and 0.9 (A/B).
3. **It collects half as often**: 22.5 collections a minute against 46.9 (A/B), because a load allocates about a third less and a rescan comes at most once a second.
4. **It holds more memory, within budget**: `Private_Dirty` 37.5 MiB mean against 26.4, with a flat slope, against ≤ 64 MiB settled (A/B).
   The live heap was 11–12 MB against 5–10; fewer collections let the heap goal sit higher.
5. **The first minute is start-up, not settled work**: both builds began at about 106% of a core catching up on the copied state directory, which puts the whole-run means at 2.2% (r890) and 3.8% (r873), and the p95s at 7.9% and 18.9%.
   That minute is judged by the first-launch budget, [item 159](../../roadmap/159-first-launch-takes-the-machine.md)'s.

## What it does not show

- **A busy afternoon on the live home.** Only 11 transcripts were written in the hour before the run, so neither build was pushed; the acceptance test above is the loaded measure, and a run with several item sessions working would show the live home's busy case.
- **A cold start.** Item 196 changes the settled daemon only; first launch is item 159's, and its report measures it.
- **Where the remaining settled CPU goes.** A profile during the acceptance test put most of what is left in each rescan's `Build`, the catalogue's stat of every stopped transcript, and the collector; making a load incremental per file would go further than this item.
- **A reference machine.** Like every report so far, this is a 14-thread laptop, not the 4-core minimum.
