# The settled city's memory after item 162, against r871, 2026-10-22

**Rig:** Intel Core Ultra 7 265U, 14 threads, 62 GiB; the city draws on the **integrated Arrow Lake-U GPU** (i915), the only GPU in the machine; 1920×1200, i3 on X11, Arch Linux, kernel 7.2.11.
It is the machine of [the r871 report](2026-10-21-ultra7-265u-igpu-r871.md), whose r871 is this report's baseline.
**Builds:** r871 (`458454f`), the build [item 162](../../roadmap/162-the-city-holds-gigabytes-of-gpu-memory.md) was re-measured against; r889 (`d100abf`), item 162's slices 1–3; each built with `go build ./cmd/botropolis` from `git archive`, go 1.27.3.
**Home:** the `metropolis` demo, 28 sessions, staged by `botropolis-demo stage`, with no daemon (`--socket` to nothing), every city's state private.
**Runs:** `perf-city`, 90 s at 2 s, one build at a time on the real display, the window focused, between 21:10 and 23:40 MDT on 2026-10-21; and the slice 4 acceptance test, under Xvfb, for each build.

## Findings

1. **The settled city meets its memory budget on the demo**: r889 held **355 MiB** of own memory and GPU memory together at fit (76 MiB `Private_Dirty`, 279 MiB GPU), against ≤ 512 MiB; r871 held 689 (310 and 379).
2. **Own memory fell by three quarters, GPU memory by a quarter.**
   Own memory is the Go heap: 141 MB live at r871 and 24 at r889.
   96 MB of r871's heap was the six z2 kit pages, which Ebitengine keeps on the CPU until an image is first drawn from, and z2 is only drawn from zoom 1.98 (slice 1); the rest was the shaping cache the group-review panel's clipping filled (slice 2).
   GPU memory fell by the 96 MiB z2 would have taken once sent, because a window now puts up only the level its camera picks (slice 3).
3. **Under Xvfb the same city holds 250 MiB against 528**, textures and all, because Mesa's software renderer keeps them in the process's own memory.
   That is now a gate: `TestSettledMemory` fails above 512 MiB, and failed on r871 (slice 4).
4. **Drawing costs about the same**: 6.6 ms a frame at r889 and 5.7 at r871 in the last report of each run, and 44% and 42% of a core; this item did not set out to change either, and items 161 and 193 own them.

## What it does not show

- **The real history**, on which the budget is set and r871 held 715–817 MiB: it needs a scratch daemon on a copy of the state directory and a focused window, and is owed.
- **Full zoom**, where slice 3 keeps z2's six pages instead of z1's two: both builds' zoomed runs drew no frame, because the desk was in use and an unfocused city draws nothing, so neither is quoted.
- **A hidden city**, which is item 163.

## Reproduce

From the meta repository's root, `T` a scratch directory, each run with its own `XDG_STATE_HOME` and `XDG_RUNTIME_DIR` so it cannot raise an open city:

```sh
botropolis-demo stage --corpus botropolis/demo/corpus --scenario botropolis/demo/scenarios/metropolis.yaml --home $T/home
performance/tools/perf-city --bin $T/r889/botropolis --seconds 90 -- --home $T/home --config $T/config.toml --socket /nonexistent/b.sock
(cd botropolis && go test -count=1 ./testing/acceptance/ -run TestSettledMemory -v)
```
