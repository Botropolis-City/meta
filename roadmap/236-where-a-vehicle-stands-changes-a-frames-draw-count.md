# 236. Where a vehicle stands changes how many draw commands a frame takes

**Open. Filed 2026-10-24 (r976), from items 221 and 222 each needing `TestTheWorkAFrameTakes`'s night ceiling raised. Nobody's call — the performance manager measures it first.**

`TestTheWorkAFrameTakes` holds the metropolis's draw commands a frame under ceilings that [item 193](193-a-still-city-is-redrawn-whole-every-frame.md) lowered to what it reached ("today's worst plus 2%"), below a target of 70.
On 2026-10-24 two items moved the night count without drawing anything more:

- [item 221](221-the-railway-is-drawn-over-the-trees.md) draws park trees through a colour matrix, which cannot share a batch with the plain kit sprites beside them: about 2–3 commands (night 39 → 42);
- [item 222](222-cars-drive-on-the-kerb-when-zoomed-in.md) moves where vehicles stand (curved bends, lot lanes, a deeper front lane): one command (night 39 → 40), with the same number of things drawn, because vehicles are drawn in the depth-sorted list among the buildings and one now falls between sprites from different atlas pages and splits a batch.

Both raises were allowed, in the open and under the target, but a count that moves with where a car happens to stand is a ratchet that will creep a command at a time.

**What to find.** Which draws split batches in the depth-sorted pass, by page and by shader, and whether movers can be drawn so their order among buildings does not decide the batching (a mover's sprites on one page, or movers batched by page within a depth band where the sort allows).
Then lower the ceilings back by whatever it saves, and add a case that moving a vehicle within its lane does not change the count.
- **A third raise** (manager, 2026-10-24): item 223 changed the metropolis scene (fewer group lines) and the count rose again, to 26 by day and 43 by night, with no code changed, so the count moves with the scene as well as with where vehicles stand. Once this item finds the batch splits, it lowers both ceilings to what a fix reaches, and the ceilings stop moving with layout.
- **No more raises until this item reports** (manager, 2026-10-24, at the performance manager's ask): the ceilings stand where items 221 and 223 left them (day 26, night 43). Item 222's approved raise stands only if its combined count after rebasing is 43 or under; above that it waits for this item's report. The performance manager takes this item now, ahead of the `make test-performance` baseline, which it does not need.
- **Interim, from the performance manager** (2026-10-24, r980, Xvfb debug build on the Ultra 7 265U): it reproduces the test (25 day, 42 night; settled frames vary 23–25 and 40–42 with where movers stand). With no movers the metropolis takes 9 by day and 14 by night, the same as the hamlet, so the still city is flat and the movers cost 16 and 28. Nearly all of that is the mover-rectangle redraw in `stillframe.go`: each rectangle is redrawn from the ground up with every building it overlaps, and `batch()` in `dirtystream.go` orders them greedily. By day one pass makes 17 commands, split across 6 source images and 3 shaders. Causes so far: linear and nearest filtering on the same page; colour-matrix draws, whose matrix `batchKey` ignores while Ebitengine splits on it (item 221's trees); and the greedy order, which overlap decides, so layout moves the count. Raw runs: `~/.local/state/botropolis-perf/item-236-r980-20261024-090143/`.
- **Root cause** (the performance manager, 2026-10-24): `drawSprite` (`pkg/render/iso.go`) draws every kit sprite with `FilterLinear` and mipmaps on, so a sprite drawn below half size samples a mipmap level of its page, and each level is its own texture (one page appears as three sources in the command log); colour-matrix draws go through `DrawRectShader`, which never uses mipmaps. `batchKey` keys on the page alone, so `batch()` groups draws the GPU cannot merge, and which level a mover's rectangle pulls in decides the count. Being priced: sprites with mipmaps off, batching that knows the level, and the trees' matrix drawn plain. Mipmaps off would also change how sprites look below half size and what the pages hold in GPU memory ([item 162](162-the-city-holds-gigabytes-of-gpu-memory.md)), so both are measured, and a look change comes to Aria as frames.
